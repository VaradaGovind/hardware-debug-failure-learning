$$\mathbf{heldout\_pipe\_src} \quad \longrightarrow \quad \text{Model Predicted: } \mathbf{d1} \quad \text{vs. Ground Truth: } \mathbf{v1}$$

This document presents the complete microarchitectural, temporal, and formal causality deconstruction of why `d1` was chosen by prior models, why `d1` is fundamentally symptomatic and incorrect, why `v1` is the true causal root cause, and how multi-step agentic investigation distinguishes them.

## 4. Deconstructing the Diagnostic Divergence (`d1` vs `v1`)

### 4.1 Why `d1` is Tempting (The Surface Bias)
1. **Symptom Category Matching**: The testbench failure log states `"FAIL: Source Pipeline Stall Bubble"` and the test harness assigns the symptom classification `"Data Loss"`.
2. **Payload Visibility**: In the candidate set `[valid_in, d_in, valid_out, d_out, v1, d1]`, the signal `d1` explicitly contains the data payload (`0xAA` / decimal `170`), whereas `v1` is a single binary bit (`0` or `1`).
3. **Apparent Value Discrepancy**: A superficial inspection sees that `d1 = 170` at $T=35$, but the downstream output port `d_out` remains `0`. The model infers: *"The data in `d1` was not delivered to `d_out`, therefore `d1` is broken."*

### 4.2 Why `d1` is Downstream, Symptomatic, and Incorrect
1. **Data Registers are Passive Slaves to Control**: In digital pipeline microarchitecture, a data register is a passive operand container. The value stored in `d1` is **architecturally undefined and irrelevant** unless the accompanying control token `v1` is asserted (`v1 == 1`).
2. **`d1` Fulfilled Its Contract**: At clock edge $T=35$, `d1` performed its precise RTL assignment (`d1 <= d_in`) by latching `0xAA`. It did not corrupt, truncate, or invert the operand.
3. **No Causal Mechanism in `d1`**: The downstream stage (`valid_out`, `d_out`) did not drop data because `d1` was corrupted; rather, the downstream stage discarded or failed to sample the stage because **the stage validity token was lost**. Blaming `d1` confuses the passive cargo with the steering mechanism.

### 4.3 Why `v1` is the Causal Root Cause
1. **Pipeline Token Conservation Law**: A standard synchronous processing pipeline satisfies a strict flow invariant: every valid transaction accepted at stage $i$ must either be retained at stage $i$ (if stalled) or transferred to stage $i+1$ (if advancing):
   $$v_1(t) \wedge \neg\text{stall}(t) \implies \text{valid\_out}(t+1) = 1$$
   $$v_1(t) \wedge \text{stall}(t) \implies v_1(t+1) = 1$$
2. **The Defect Mechanism (`PIPE_STALL_BUBBLE`)**:
   At $T=35$, the pipeline accepted a valid token (`v1 = 1`). At $T=45$, stage 2 failed to assert `valid_out <= 1`, AND stage 1 cleared `v1 <= 0`. The transaction token was erased from the pipeline state registers, creating an unrecoverable "bubble".
3. **First Causal Divergence**:
   The earliest cycle at which the physical hardware state diverged from the architectural specification occurred at **$T=35 \rightarrow T=45$**:
   - `v1` dropped to 0 without retiring the token downstream.
   - The failure of `valid_out` to assert and the absence of data on `d_out` at $T=70$ are purely downstream consequences of this upstream token loss.
4. **Root Cause Signal**: `v1` is the internal state register whose anomalous deassertion generated the bubble.
